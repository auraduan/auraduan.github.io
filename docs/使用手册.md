## 1. 改什么，去哪里

| 要改什么 | 改这里 |
|---|---|
| 站名 / 副标题 / 描述 / 域名 | `src/site.config.ts` → `SITE` |
| 你的名字、身份说明 | `SITE.author` / `SITE.role` |
| 个人简介正文 | `src/data/about.md` |
| 个人照片 | `src/assets/portrait.png`（jpg / webp / avif 均可） |
| 主页按钮（GitHub / 小红书 / Instagram / 网易云） | `PROFILES` |
| **音乐页的介绍文字** | `MUSIC.intro` |
| **音乐页「正在听」/ 收听榜** | `src/data/now-playing.json` · `src/data/listening-stats.json` |
| 导航栏 / 工具页 / 页脚 | `NAV` / `LINK_GROUPS` / `SOCIAL` |
| 首页壁纸 | `src/assets/wallpapers/`（见 §6） |
| 文章 / 专辑 / 歌手 | `src/content/` 下对应目录（见 §2–§4） |

两条提醒：

- **`PROFILES` 只填干净地址**。App 分享出来的链接带 `xsec_token` / `stkn` 之类追踪参数，几周后会失效。
- **改名字改 `SITE.author` 一处**（关于页标题 / 浏览器标签 / 页脚署名 / RSS 作者会同步）；但 `SITE.description` 里的名字写在句子中，要手动改。

## 2. 文章

```
src/content/posts/我的文章/index.md   ← 目录式：文章自带配图时用
src/content/posts/我的文章.md         ← 扁平式：无配图时用
```

两者 URL 都是 `/posts/我的文章`。**目录名 / 文件名即 URL**：用英文或拼音、别带空格、**发布后不要改**（外链失效）。文件名以 `_` 开头会被忽略（`_草稿.md`）。

**删除**：直接删目录，没有别处需要同步。

```yaml
---
title: "标题"              # 必填，≤60 字
description: "一句话摘要"   # 必填
publishedAt: 2026-10-06    # 必填
category: "机器人"          # 必填，单值
tags: ["ROS2", "SLAM"]     # 可选
updatedAt: 2026-10-08      # 可选，填了显示「更新于」
cover: "./cover.jpg"       # 可选，放文章同目录
coverAspect: "auto"        # 可选，默认按真实尺寸识别，不用填
draft: false               # true = 不发布
album: "in-rainbows"       # 可选，关联专辑 id；多张写 ["a", "b"]
toc: true                  # 可选，右侧目录
math: false                # 用了公式必须改 true
---
```

| 字段 | 要点 |
|---|---|
| `category` | **单值、稳定**（分类少而稳；标签多而随意） |
| `album` | 关联专辑 id（`src/content/albums/` 下的**目录名**）。**一张写字符串，多张写数组**（如一首单曲 + 它后来被收录的专辑），数组顺序即展示顺序。填了之后**双向通**：文章底部出现「相关专辑」出口，专辑页的「写过的相关文章」里也会列出本文。写错 id 不中断构建，只在控制台提示 |
| `cover` | 相对**本文所在目录**；有封面就走目录式 |
| `draft` | 不进构建 / 列表 / RSS |
| `math` | **忘了开，公式会渲染成散乱的样子** |

> 正文**不要再写 H1** —— 标题由 frontmatter 出，再写一次会重复。

## 3. 专辑与单曲

一张专辑一个目录，**目录名即 URL** `/albums/<id>`：

```
src/content/albums/in-rainbows/
├── index.md          ← 文件名固定，不能改
└── cover.png         ← 建议就叫 cover
```

```yaml
---
title: "In Rainbows"        # 必填
artist: "Radiohead"         # 必填
year: 2007                  # 必填，整数
type: LP                    # 可选，发行形态：LP / EP / Live / 精选 / 单曲
language: "粤语"             # 可选，演唱语种，驱动专辑墙的「语种」筛选
cover: "./cover.png"        # 必填
rating: 9.5                 # 可选 0–10
genre: ["Alt Rock"]         # 可选，流派
mood: ["深夜", "写代码"]      # 可选，会变成专辑墙的「心情」筛选按钮
listenedAt: 2026-09-12      # 可选，影响排序
pick: true                  # 可选，进首页「在听什么」
link: "https://..."         # 可选，可填网易云专辑页
draft: false
---
短评正文，支持 Markdown。
```

**`type`（发行形态）** —— 填了就会在卡片标题前显示一个小标记，并成为专辑墙的一行筛选：

| 值 | 含义 | 显示标记 |
|---|---|---|
| `LP` | 正式录音室全长专辑（**常态**） | **否**（标了反而成噪音） |
| `EP` | 迷你专 | 是 |
| `Live` | 现场录音 | 是 |
| `精选` | 个人精选 | 是 |
| `单曲` | 单曲碟（一张碟 2–4 首） | 是 |

- **单值** —— 一张专辑只填一个。真有交叉时（如「演唱会精选」）选最主要的一面，补充说明写进正文
- **不填 = 不显示标记**，也不进筛选
- 筛选栏的候选**只从实际数据里汇总**，所以不会有空按钮；以后加了 EP，它自己就长出来
- ⚠ `单曲` 指**单曲碟**（一张碟 2–4 首），按「作品」收录 —— 一首歌不单独建条目，见下方曲目表

**`language`（语种）** —— 填了就会成为专辑墙的一行「语种」筛选，**但不在卡片上显示标记**（它只回答「属于哪一类」，不是「这张特别在哪」）。

- 写中文：`粤语` / `国语` / `英语`……
- **为什么不做「港 / 台 / 内地」**：那是**歌手的身份归属**，不是音乐本身的属性 —— 歌手常有多重身份（北京出生、香港出道），归属会一直扯不清；而「歌用什么语言唱」是事实，也直接影响听感。你的收藏全是粤语，按地区分只会有一个「香港」，等于白做

**目录名规则**（它一身三职：专辑 id、URL、文章 `album:` 的关联键）

1. **只能一层** —— `albums/2026/xxx/` 会**构建失败**，报错 `Missing parameter: id`（完全看不出跟目录结构有关）
2. **小写英文 + 连字符** —— `in-rainbows`、`live-2024`
3. **别用中文 / 空格 / 大写** —— 中文能跑但链接会变成 `%E6%B0%B8...`；大写有大小写敏感的雷
4. 排序看 `listenedAt`（无则看 `year`）、显示看 `title` / `artist`，**都与目录名无关**

### 曲目表（专辑里有什么歌）

写在专辑的 frontmatter 里，**顺序即展示顺序**（不排序 —— 曲序有时是作品的一部分）。

```yaml
tracks:
  - "一种永远"
  - "心之科学"
  - title: "东京人寿"          # 三种写法可混用
    note: "黄伟文的词把「人寿」和「东京」并排放在一起……"
```

| 写法 | 什么时候用 |
|---|---|
| `- "歌名"` | 只是记个曲目 |
| `- title: "歌名"` + `note: "……"` | **某首歌值得单独说两句** —— 会在标题下多一行小字 |
| `- disc: "CD 1"` + `tracks:` | **双碟以上**（演唱会专辑居多）用它分碟 |

**双碟以上按碟分节** —— 页面会在碟与碟之间画一条分隔线，并且**编号按碟重新起算**：

```yaml
tracks:
  - disc: "CD 1"
    tracks:
      - "今天等我来"
      - "好歌献给你"
  - disc: "CD 2"
    tracks:
      - "人车志"
```

- 不填 `tracks` → 整块「曲目」**不渲染**，不留空标题
- 单碟专辑**直接平铺**（不用 disc），渲染成一路编号到底
- 专辑页会把它渲染成编号列表（`01` `02` …）

**给某首歌挂上单独的乐评**（不用为那首歌另建页面）：

```yaml
# 在这篇乐评文章里
album: "joey-schrodingers-cat"   # 哪张专辑
track: "东京人寿"                 # 专辑里的哪首歌
```

专辑的曲目表会反查出这篇，把那首歌变成链接并标「**乐评 →**」。

> **关联写在文章上，专辑页反查** —— 所以新写一篇乐评，不必回头改专辑文件。
> `track` 的标题要与 `tracks` 里的**一字不差**（会自动 trim 再比），对不上构建时会提示。

## 4. 歌手（自动汇总 + 可选档案）

歌手页**不是手写的清单** —— 由专辑的 `artist` 字段自动汇总。档案只用来给喜欢的歌手补头像、评分与介绍。

```
src/content/artists/chen-hui-xian/
├── index.md
└── avatar.png       ← 可选，不填显示占位块
```

```yaml
---
name: "陈慧娴"           # 必填，必须与专辑里的 artist 一字不差
avatar: "./avatar.png"   # 可选
rating: 9.2              # 可选 0–10
link: "https://..."      # 可选
---
这里写介绍，支持 Markdown。
```

| 你想做的 | 要做的 |
|---|---|
| 加一张新专辑 | 照常写专辑目录，**歌手页会自动多一条作品**，不用管 |
| 让某位歌手「有名有姓」 | 建一份档案，补头像与评分 |
| 名字写错了 | 不用自己找 —— **构建会报警**告诉你哪个名字对不上 |

> **不建档案也能跑**：歌手墙上是朴素占位卡，但网址会退回**中文名**（一长串 `%E9%99%88...`）。想要干净网址就补档案。

## 5. 音乐页（`/music`）

从上到下：**播放器开场（正在听）→ 统计表 → 专辑网格（+ 随机抽一张）→ 歌手 → 收听榜 → 网易云入口**。

### 开场介绍文字

`src/site.config.ts` → `MUSIC.intro`，**一行一段**，想写几行写几行：

```ts
intro: [
  '听过并想留下几句话的唱片，以及围绕它们的那些人。',
  '不追新，只记下真正反复听过的。',
],
```

留空数组（`intro: []`）则整段不显示。

### 「正在听」

`src/data/now-playing.json` —— **改一次就更新一次**：

```json
{
  "title": "千千阕歌",
  "artist": "陈慧娴",
  "album": "pc-always-your-friends",
  "note": "这周又在循环"
}
```

- `album` 填**专辑目录名**：填对上就显示那张封面，对不上（或留空）只显示文字，**不会报错**
- `note` 是那句手写话
- **清空这个文件 = 关掉播放器开场**，页面会自动退回普通标题

### 收听榜

`src/data/listening-stats.json`：

```json
{
  "source": "网易云音乐",
  "scope": "不含其他平台的收听记录",
  "updatedAt": "2026-10-10",
  "tracks": [{ "title": "千千阕歌", "artist": "陈慧娴", "plays": 633 }]
}
```

- **`updatedAt` 别忘了改** —— 页面上会露出「截至 X」，它是这个数字诚实的凭据
- **`scope` 那行别删** —— 网易云只统计它自己 App 内的播放，不说明就等于把「网易云播放次数」说成「总收听量」
- 数字**手工录入**，不接任何 API。建议**月更**，不必追周更

> 上面两段里的 `//` 只是讲解用的标注，JSON 文件里不能真的写注释。

### 随机抽一张

专辑网格标题行右侧的按钮，随机跳一张专辑详情页。URL 列表在**构建时**生成，纯前端零依赖。

## 6. 壁纸

放 `src/assets/wallpapers/`，**文件名顺序 = 轮播顺序**（用 `01-` `02-` 前缀）。

- 建议 3–5 张，横构图 **1920×1080 以上**，单张 **≤ 300KB**
- 只有 1 张时自动不轮播；间隔改 `WALLPAPER_INTERVAL_MS`（默认 7000，**不要低于 6000**）
- 想给明暗模式分别配图（留空则回退共用图）：

```
src/assets/wallpapers/01-a.jpg       共用
src/assets/wallpapers/light/01-a.jpg 仅浅色模式
src/assets/wallpapers/dark/01-a.jpg  仅深色模式
```

> 用深色调图片效果最好 —— 首屏标题是白字，压在上面必须有足够对比度。

## 7. 导航与页脚

全在 `src/site.config.ts`：

- `NAV` —— 导航栏，某项带 `children` 就变成下拉菜单
- `LINK_GROUPS` —— `/links` 工具页的分组列表
- `SOCIAL` —— 页脚，`href` 留空则不渲染该项

外链**自动**加 `target="_blank" rel="noopener"`。

## 8. 公式、代码、图片

**公式**（LaTeX）—— **必须**在 frontmatter 写 `math: true`：

```markdown
行内写 $x = \frac{-b \pm \sqrt{b^2-4ac}}{2a}$

独立成行：
$$
T = \begin{bmatrix} a & b \\ c & d \end{bmatrix}
$$
```

三个坑：

- **标题里不要写行内公式**（如 `### 1.2 常用范数（$1$、$2$ 范数）`）—— 目录文字从标题原样提取，而 KaTeX 会同时吐出三份文本，目录里会显示成「111、222」
- **不要单独升级 `katex`** —— 它与 `rehype-katex` 内置的版本必须一致（现锁 `0.16.47`），否则上下标会挤成一团
- **矩阵觉得挤**：在那个数学块里写 `\def\arraystretch{1.6}`（只对这一个块生效）

**代码块** —— 语言名自动显示在标题栏。想覆盖成文件名：

````markdown
```python title="demo.py"
```
````

**图片** —— 放 `src/` 下（文章配图放文章目录），**不要放 `public/`**（会绕过优化管线，不生成 WebP/AVIF 与响应式尺寸）。

**图注** —— 图片下面紧跟一行**斜体**即可，样式已内置（自动变成次要墨色的小字，左对齐）：

```markdown
![加速度计简图](./accelerometer.png)

*图 1　加速度计简图*
```

> **深色主题会给正文图片垫一层浅底**（`global.css` 的 `.dark .prose-article img`）。示意图多是黑描边 + 彩填充的线稿，不垫底在深色下会「黑吃黑」。不透明照片会盖住这层底，视觉上毫无变化 —— 所以这条规则对所有正文图片都安全。

**从 Word 导入** —— `.docx` 里的内嵌公式是 MathType 的 **WMF 位图，浏览器不认**，必须重建成 LaTeX。图片在解包后的 `word/media/` 里。WMF 可先用 Windows GDI 渲染成 PNG 供肉眼核对（`Pillow` 在 Windows 下能直接读 WMF；`System.Drawing` 的 `Metafile` 也行，但要用 PowerShell 工具调用）。

## 9. 写作、预览、发布

| 命令 | 用途 | 改源码会自动更新？ |
|---|---|---|
| `npm run dev` | **日常写作就用这个**（localhost:4321） | ✅ 立刻 |
| `npm run build && npm run preview` | 看**真实构建产物** | ❌ 不监听 |
| `git push` | 发布（自动部署） | — |

**改完必须重启 dev 的只有两个文件**：`astro.config.ts`、`src/content.config.ts`。其余（文章 / 配置 / 组件 / 样式）都自动刷新。

> ⚠ **`astro preview` 不监听源码** —— 它只把 `dist/` 里**上一次构建**的文件端出来。**改了东西看不到变化，九成是看错了服务器。**
>
> ⚠ **用 `npm run build`，不要用 `npx astro build`** —— 前者构建后会自动跑 Pagefind 生成搜索索引，后者不会（preview 里搜索会一直显示「索引尚未生成」）。

**发布**：

```bash
git add -A && git commit -m "新文章：xxx" && git push
```

推完在仓库 **Actions** 标签页看进度，约 1–2 分钟。站点：`https://auraduan.github.io/`

> **推送后要验收线上**：逐路由看状态码 + 抓线上 CSS 确认含最新改动。CDN 有缓存，会出现「首页 200 但资源还是旧的」。

## 10. 站内小功能

| 功能 | 怎么用 | 注意 |
|---|---|---|
| **搜索 / 命令面板** | 页眉 🔍 按钮，或键盘 **Ctrl + K**（Mac ⌘K）；↑↓ 选择、Enter 打开、Esc 关闭 | 搜文章 / 专辑 / 固定页面。**dev 下没有索引是预期的**（显示降级提示），preview 与线上才可用 |

| **唱片机** | 任意专辑详情页，**点一下封面** | 黑胶滑出并旋转，再点收回 |

## 11. 出问题了

| 现象 | 原因 |
|---|---|
| **改了代码，页面不变** | 按顺序查：① 看的是 `astro preview`（不监听源码）？② 改的是那两个需重启的文件？③ Ctrl+F5 强刷 |
| 提示端口 4321 被占用 / 地址变成 4322 | 已有一个 dev 在跑。先在原终端 `Ctrl + C` 停掉，再启动 |
| 构建报错提到某个字段 | frontmatter 字段名写错或漏填必填项 —— 校验是严格的，这是有意的 |
| 文章没出现 | 查三处：`draft: true`、文件名以 `_` 开头、文件不在 `src/content/posts/` 下 |
| 公式渲染散乱 | frontmatter 忘了 `math: true` |
| 搜索面板一直显示「索引尚未生成」 | ① dev 下 —— 正常；② preview 下 —— 构建时用了 `npx astro build`，改用 `npm run build` |
| 图片没优化 / 加载慢 | 图放进了 `public/`，改放 `src/` |
