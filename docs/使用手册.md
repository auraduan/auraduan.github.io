# 博客使用手册

> 当前版本 v1.8 · 配套设计说明见 `需求方案.md`
> 全站配置**只有一个入口**：`src/site.config.ts`

---

## 1. 素材都在哪里

要改站上的内容，照这张表找。**全部集中在 `src/site.config.ts` 一个文件里**，不用碰组件代码。

| 要改什么 | 改这里 |
|---|---|
| 博客名称 / 副标题 | `src/site.config.ts` → `SITE.title` / `SITE.subtitle` |
| 站点描述（SEO / RSS） | `src/site.config.ts` → `SITE.description` |
| 你的名字（关于页大标题 / 浏览器标签 / 页脚署名 / RSS 作者） | `src/site.config.ts` → `SITE.author` |
| 站点域名 | `src/site.config.ts` → `SITE.url` |
| 名字下方那行身份说明 | `src/site.config.ts` → `SITE.role` |
| 个人简介正文 | `src/data/about.md` |
| 个人照片 | `src/assets/portrait.png`（支持 jpg / webp / avif，换扩展名即可） |
| 首页壁纸 | `src/assets/wallpapers/` |
| 导航栏 / 工具页 / 页脚 | `src/site.config.ts` → `NAV` / `LINK_GROUPS` / `SOCIAL` |
| 示例文章（3 篇） | 删掉 `src/content/posts/` 下对应目录 |
| 专辑 | 见 §4，一张一个目录 |

> 代码里还留着 `TODO(令宸)` 的地方＝**仍是示例内容、等你替换**。目前剩两处：`NAV` 里的工具下拉项、`LINK_GROUPS` 的工具清单。
>
> `SITE.url` 必须与线上域名一致，否则 RSS、Sitemap 里的绝对链接会指错。
>
> **改名字时**：`SITE.author` 是唯一源头，改一处，关于页标题、浏览器标签、页脚署名、RSS 作者会同步更新。但 `SITE.description` 里也有一处名字，它是**写在句子中的**（不是变量），需要手动一并改。

## 2. 壁纸

放 `src/assets/wallpapers/`，**文件名顺序 = 轮播顺序**（用 `01-` `02-` 前缀）。

- 建议 3–5 张，横构图 **1920×1080 以上**，单张 **≤ 300KB**
- 只有 1 张时自动不轮播
- 轮播间隔：`src/site.config.ts` → `WALLPAPER_INTERVAL_MS`（默认 7000，**不要低于 6000**）
- 想给明暗模式分别配图，放子目录（留空则自动回退到共用图）：

```
src/assets/wallpapers/01-a.jpg       共用
src/assets/wallpapers/light/01-a.jpg 仅浅色模式
src/assets/wallpapers/dark/01-a.jpg  仅深色模式
```

> 用深色调图片效果最好——首屏标题是白字，压在上面必须有足够对比度。

## 3. 文章

### 新增

```
src/content/posts/我的文章/index.md   ← 目录式：文章自带配图时用
src/content/posts/我的文章.md         ← 扁平式：无配图时用
```

两者 URL 都是 `/posts/我的文章`。**文件夹名 / 文件名即 URL**，所以：

- 用英文或拼音更稳，别带空格
- **发布之后不要改**，外链会失效
- 文件名以 `_` 开头会被整篇忽略（`_草稿.md`）

### 删除

直接删掉整个目录或文件即可，没有别处需要同步。

### frontmatter 速查

```yaml
---
title: "标题"                    # 必填，≤60 字，超长构建会报错
description: "一句话摘要"        # 必填，列表页与搜索用
publishedAt: 2026-10-06           # 必填
updatedAt: 2026-10-08             # 可选，填了显示「更新于」
category: "机器人"                # 必填，单值
tags: ["ROS2", "SLAM"]            # 可选，数组
cover: "./cover.jpg"              # 可选，图片放文章同目录
coverAspect: "auto"               # 可选，见下
draft: false                      # true = 不发布
album: "in-rainbows"              # 可选，关联专辑 id
toc: true                         # 可选，右侧目录开关
math: false                       # 用了公式必须改 true
---
```

| 字段 | 要点 |
|---|---|
| `category` | **单值**、稳定，如「机器人」「随笔」。与「标签」的区别：分类少而稳，标签多而随意 |
| `tags` | 数组，可随时加。标签/分类页会自动生成 |
| `cover` | 相对**本文所在目录**的路径 |
| `coverAspect` | 默认 `auto`——按图片真实尺寸自动识别，**不用手填**。想强制统一才写 `"16:9"` `"3:2"` `"4:3"` `"1:1"` |
| `draft` | `true` 时不进构建、不进列表、不进 RSS |
| `math` | **默认 false**。忘了开，公式会渲染成散乱的样子 |

## 4. 专辑

一张专辑一个目录，**目录名即 URL** `/albums/<id>`：

```
src/content/albums/in-rainbows/
├── index.md
└── cover.png        ← 文件名建议固定为 cover
```

```yaml
---
title: "In Rainbows"        # 必填
artist: "Radiohead"         # 必填
year: 2007                  # 必填，整数
cover: "./cover.png"        # 必填
rating: 9.5                 # 可选，0–10，一位小数
genre: ["Alt Rock"]         # 可选，数组
mood: ["深夜", "写代码"]      # 可选，数组
listenedAt: 2026-09-12      # 可选，影响排序
pick: true                  # 可选，进首页「在听什么」
link: "https://..."         # 可选，可填网易云专辑页
draft: false
---

短评正文，支持完整 Markdown。
```

- `mood` 会自动汇总成专辑墙顶部的**筛选按钮**，用词保持统一（别一会儿「深夜」一会儿「晚上」）
- `pick: true` 的会出现在首页

### 目录名怎么起（有讲究）

目录名一身三职，所以**不能随便起**：

| 它是什么 | 影响 |
|---|---|
| 专辑 id | 文章里 `album:` 的值要和它**逐字符相同**，否则关联失效 |
| URL | `/albums/<目录名>`，改了就是换网址，外链全废 |
| —— 排序 | **不受影响**，排序看 `listenedAt`（无则看 `year`） |
| —— 界面显示 | **不受影响**，页面上显示的是 `title` / `artist` 字段 |

**规则**：

1. **只能用一层目录。** `albums/2026/xxx/` 这种按年份嵌套会**直接构建失败**，报错是 `Missing parameter: id`——完全看不出跟目录结构有关
2. **小写英文或拼音 + 连字符**：`in-rainbows`、`yongyuan-shi-ni-de-pengyou`
3. **不要用中文、空格、大写**。中文能跑，但链接会变成一长串 `%E6%B0%B8...`，分享出去很难看；大写有风险——Windows 文件系统不区分大小写，线上 URL 区分
4. **重名就加年份**：`live-2024`、`live-2026`
5. 中文标题照常写进 `title` 字段，**跟目录名无关**

```bash
# 正确
src/content/albums/forever-your-friend/index.md

# 会构建失败
src/content/albums/2026/forever-your-friend/index.md

# 能跑但链接难看
src/content/albums/永远是你的朋友/index.md
```

> `index.md` 这个**文件名不能改**——专辑的匹配规则就是 `**/index.md`，没有文章的「扁平式」写法。

## 5. 导航与工具页

全在 `src/site.config.ts`：

```ts
export const NAV = [
  { label: '文章', href: '/posts' },
  {
    label: '工具',
    href: '/links',
    children: [                                  // 有 children 就变成下拉菜单
      { label: 'GitHub', href: 'https://github.com', desc: '代码托管' },
    ],
  },
];
```

- `LINK_GROUPS` → `/links` 页的分组列表
- `SOCIAL` → 页脚（`href` 留空则不渲染，可用于临时隐藏）
- 外链**自动**加 `target="_blank" rel="noopener"`

## 6. 公式、代码与图

**公式**（LaTeX 语法）：

```markdown
行内写 $x = \frac{-b \pm \sqrt{b^2-4ac}}{2a}$
独立成行：
$$
T = \begin{bmatrix} a & b \\ c & d \end{bmatrix}
$$
```

> 用公式**必须**在 frontmatter 写 `math: true`。

**代码块**：语言名会**自动**显示在标题栏，不用手写。

````markdown
```python
print("语言名自动出现在标题栏")
```
````

想显示文件名，显式写 `title` 覆盖：

````markdown
```python title="demo.py"
```
````

**图片**：放 `src/` 下（文章配图放文章目录），**不要放 `public/`**——放 public 会绕过优化管线，不生成 WebP/AVIF 与响应式尺寸。

## 7. 本地预览与发布

### 开启热重载（日常写作就用这个）

热重载 = **改完文件浏览器自动刷新**，不需要手动 build、也不需要手动刷新页面。

```bash
cd E:\Blog
npm run dev
```

**起来的标志**：终端出现这几行，就成功了。

```
  astro  v7.x  ready in xxx ms

  ┃ Local    http://localhost:4321/
```

然后用浏览器打开 **http://localhost:4321/**（这个地址别关终端，终端一关服务就停）。

**从此刻起，改这些文件都会自动刷新**：

| 改什么 | 是否自动刷新 |
|---|---|
| 文章 `.md`、`src/data/about.md` | ✅ 立刻 |
| `src/site.config.ts`（站名 / 导航 / 壁纸间隔） | ✅ 立刻 |
| 组件 `.astro`、样式 `.css` | ✅ 立刻（页面不闪、局部更新） |
| `astro.config.ts`、`src/content.config.ts` | ❌ **必须重启**（见下） |

**关闭 / 重启**：

```bash
# 在跑着 dev 的终端里按 Ctrl + C 即可停止
npm run dev          # 重新启动
```

> **不要重复开**。已经有一个 dev 在跑时，再执行一次 `npm run dev` 会提示端口 4321 被占用（或自动换到 4322），容易让你在两个地址之间看到不同内容。要开先停掉旧的。

> **没反应怎么办**：先确认浏览器地址是不是 `localhost:4321`（而不是 `astro preview` 的产物，见下一节）；再确认改的是不是上面那两个必须重启的文件；最后 **Ctrl+F5 强制刷新**一次（普通刷新可能命中浏览器缓存）。

### 两个服务器别搞混（高频坑）

| 命令 | 改源码会更新吗 | 用途 |
|---|---|---|
| `npm run dev` | **会** —— 改完自动刷新 | **日常写作就用它** |
| `npx astro preview` | **不会** | 只看构建产物长什么样 |

> ⚠ **`astro preview` 不监听源码。** 它只是把 `dist/` 里**上一次构建**的静态文件端出来，改了配置或文章之后它会永远显示旧内容。
>
> 两个命令默认都用 **4321** 端口，同时开要么冲突、要么让你产生「一会儿新一会儿旧」的错觉。
>
> **改了东西看不到变化，几乎都是看错了服务器——不是热重载坏了。**

只在需要验证**真实构建产物**时才用 preview（比如改了图片处理、想确认最终体积）：

```bash
npx astro build && npx astro preview
```

### 发布

```bash
git add -A
git commit -m "新文章：xxx"
git push               # 推送即自动部署
```

推完在仓库 **Actions** 标签页能看到构建进度，约 1–2 分钟。站点：`https://auraduan.github.io/`

## 8. 首次发布（已完成，只留结论）

已于 2026-10-06 完成，**以后不用再执行**。三条结论：

- 仓库 `auraduan.github.io` 必须 **Public**；建仓时**不要**勾初始化 README / .gitignore / license（本地已有，远程初始化会让首次 push 被拒）

> **推送后怎么确认真的好了**：别只看 Actions 页面的绿勾，要**打线上地址**——逐路由看状态码，再抓一下线上 CSS 里有没有你最新的改动。CDN 有缓存，会出现「首页 200 但资源还是旧的」。

## 9. 速查：出问题了

| 现象 | 原因 |
|---|---|
| **改了代码，页面不变** | 按顺序查：① 看的是 `astro preview`（不监听源码）？② 改的是 `astro.config.ts` / `content.config.ts`（需重启）？③ Ctrl+F5 强刷。详见 §7「开启热重载」 |
| 改完要重启 dev 才生效 | 正常：只有 `astro.config.ts` 与 `src/content.config.ts` 需要重启 |
| 提示端口 4321 被占用 / 地址变成 4322 | 已经有一个 dev 在跑。先在原终端 `Ctrl + C` 停掉，再启动 |
| 构建报错提到某个字段 | frontmatter 字段名写错或漏填必填项——校验是严格的，这是有意的 |
| 文章没出现 | 查三处：`draft: true`、文件名以 `_` 开头、文件不在 `src/content/posts/` 下 |
| 公式渲染散乱 | frontmatter 忘了 `math: true` |
| 图片没优化 / 加载慢 | 图放进了 `public/`，改放 `src/` |
| 点了目录，标题被页眉挡住 | 不该发生，已用 `scroll-margin-top` 修好；若出现说明 `--header-h` 与导航高度脱节 |
| 推送后 Actions 失败 | 看日志。部署链路踩过的坑（esbuild 平台二进制）已在 workflow 里处理 |
| 想改导航栏高度 | 改 `Nav.astro` 的 `h-12`，**必须同步改** `global.css` 的 `--header-h`，否则锚点跳转会错位 |
