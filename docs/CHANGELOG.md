## 2026-11-01 傍晚（六）· 修 CI：删掉过时的 esbuild 补二进制步骤

**现象**（线上 Actions `build` 挂在这一步）：

```
Run ESBUILD_VERSION=$(node -p "require('esbuild/package.json').version")
Error: Cannot find module 'esbuild/package.json'
```

**根因**：这一步是 v1.x 时代的补丁——当时 Astro 6 / Vite 6 用 esbuild，而锁文件缺平台可选依赖，
于是用 `npm install --no-save "@esbuild/linux-x64@<已装版本>"` 事后补。

Astro 7 + Vite 8 把打包器换成了 **Rolldown**，`esbuild` 已**整个从依赖树里消失**：

| 检查 | 结果 |
|---|---|
| `node -p "Object.keys(require('./node_modules/astro/package.json').dependencies)"` | 有 `rolldown`，**无 esbuild** |
| `node -p "require('./node_modules/vite/package.json').version"` | 8.3.5，依赖 `lightningcss / rolldown`，**无 esbuild** |
| 锁文件里含 esbuild 的条目 | **0 条** |

补丁失去了存在的理由，只剩副作用：`require('esbuild/package.json')` 必然 MODULE_NOT_FOUND。

**修法**（`.github/workflows/deploy.yml`）：
1. **删除**「补齐 esbuild 平台二进制」整步
2. 安装从 `npm install --ignore-scripts` 回到 **`npm ci --ignore-scripts`**——锁文件现在完整，
   四个平台二进制实测都在：`@rolldown/binding-linux-x64-gnu` · `@img/sharp-linux-x64` ·
   `@tailwindcss/oxide-linux-x64-gnu` · `lightningcss-linux-x64-gnu`
3. 注释重写：不再讲 esbuild 的旧坑，改为写明「补丁会过期，换打包器时要回头清」

**本地验证**（按 CI 的方式完整跑了一遍）：
- `npm ci --dry-run --ignore-scripts` → 锁文件与 `package.json` 同步
- `npm ci --ignore-scripts` → 320 个包，`@rolldown/binding-win32-x64-msvc` 到位
- `npm run build` → **106 页** + Pagefind 索引 106 页 / 5694 词，零告警

> **本地验证时踩的坑**：`astro dev`（PID 5488）正开着，`lightningcss.win32-x64-msvc.node` 被进程占用，
> `npm ci` 删不掉 → `EPERM unlink`，node_modules 被删了一半卡在残废状态。停掉 dev 进程后重装正常。
> **以后本地跑 `npm ci` 前先停 dev server。**（dev 已停止，需要重新 `npm run dev`。）

## 2026-11-01 傍晚（四）· 窄屏黑胶不再压在封面上

**令宸指出**：移动端专辑页，黑胶整个盖在封面**上面**，封面只剩四边一圈黄边。

**根因**（`albums/[id].astro` 的 `@media (max-width: 639px)`）：当初为了让黑胶在窄屏「看得见」，把 `z-index` 从 0 提到 20、`left: 50%` 居中、`width: 78%` —— 等于把唱片摆在封面上。桌面那套「藏在封面后、滑出月牙」的层次在窄屏被丢掉了，而这层前后关系正是这台唱片机的隐喻本身。

**修法**：窄屏回到与桌面同一套逻辑——`z-index: 0`（封面之后）、`right: 0`（右缘与封面齐平，静止时完全被盖住），点击后 `translateX(22px)` 滑出。

**22px 是布局给的，不是设计给的**：窄屏容器右缘到视口只剩 `px-6` 的 24px，再多就撑出横向溢出（留 2px 余量）。露出的那道月牙靠盘面 4 道 conic 彗尾读转动——这套纹路本来就是按「窄月牙」配的。

**验收**（390×844，CDP 实测）：
- 静止：黑胶右缘 366 = 封面右缘 366，完全藏在后面；`scrollWidth - clientWidth = 0`
- 点击后：右缘 388 / 视口 390，**露出 22px**，`overflow = 0`；截图确认封面主体完整、唱片只从右侧探出
- 桌面 1440 回归：露 40px、`overflow = 0`，行为未变

## 2026-11-01 · 四期：阅读体验（提示框 / 图片放大 / 合集 / OG 论证）

四项一起落，需求方案升到 **v3.4**（新增 §4.5、§6.14、§6.15、§7.11）。

**1. 提示框（Admonition）** —— `src/lib/remark-admonitions.ts`（自研 remark 插件，零依赖）+ `global.css` 的 `.callout`。
写法沿用 GitHub Alerts 形状：`> [!注意]` / `[!提示]` / `[!实验结果]` / `[!前置知识]` / `[!常见错误]`，英文别名（NOTE / TIP / WARNING…）大小写不敏感。
**改的是 mdast 的 `hName` / `hProperties` 而不是吐 HTML 字符串**，所以后续插件（CJK 间距、代码语言标注）与嵌套的代码块、公式照常工作。
图标走 CSS `mask` + `currentColor`，一份 data-URI 按类型挂 CSS 变量，颜色跟着类型色走。
**注册顺序必须在 `remarkCjkSpacing` 之前**，否则标记文本会被插细空格、正则失配（已写进 §9 坑位 20）。
现有内容只动了两处纯样式型引用块（C++ 教程的「注意：」与「💡tips：」），其余引用块（含大量歌词引用）一个字节没改。

**2. 图片放大与图注** —— `src/components/ImageZoom.astro`，挂在文章页 `</article>` 之后。
点图全屏，滚轮 / 捏合 / 按钮缩放（1×–5×，以光标为锚点）、放大后拖动、`←` `→` 翻同篇的图、`Esc` 关闭、点空白关闭；
**图注自动读「图片下紧跟的一行斜体」**（既有约定，一篇文章都不用改），没有则退回 `alt`；取图用 `currentSrc`，等于点开就是最大可用尺寸。
无障碍：`role="dialog"` + 焦点锁在弹层内 + 关闭后还给触发元素；无 JS 时只是一个点不动的图。
**踩到的坑**：组件原本排在 `<article>` 之前，而带 `data-astro-rerun` 的脚本是**内联普通 script、就地执行**——
执行那一刻 `.prose-article` 还不存在，`is-zoom-ready` 打不上，光标就不会变成放大镜。改为放在 `</article>` 之后 + `astro:page-load` 兜底。

**3. 合集与学习路线** —— 新增 `collection` 集合（`src/content/collections/<id>.md`）+ `/collections`、`/collections/[id]` + 文章页合集条与章节表 + 导航「合集」。
章节关系**写在文章上**（`collection` + `collectionOrder`），合集页反查 —— 与「文章 → 专辑」同一套方向，加一章不必回头改合集文件。
**排序不看发布时间**：Python 基础三篇同为 `2026-10-13`，时间戳相同、顺序会随机，所以一律走 `seriesOrder`。
已建三条线：`python-basics`（3 章）、`flight-control`（2 章）、`cpp-from-c`（1 章，连载中）。六篇文章补了 `series` / `seriesOrder`。

**4. OG 分享卡片：论证后暂缓** —— 结论与证据见 §7.11。
关键实测：sharp + SVG 文本这条路，**librsvg 完全忽略 `@font-face`**（有无 font-face 的两张输出 MD5 相同），中文只能靠系统字体；

新增 `public/og-default.png`（1200×630 / 29 KB）给无封面的文章与固定页兜底。

## 2026-10-10 · 修内联脚本的 TypeScript 语法（线上故障）

**现象**：全站搜索点击无反应、文章目录不跟随滚动、专辑页黑胶开关失效 —— 但本地 
> auraduan-blog@0.1.0 dev
> astro dev 一切正常。

**根因**：带 `data-astro-rerun` 的 `<script>` 被 Astro **内联输出、不经 esbuild 转译**，于是脚本里的 TypeScript 语法（`import.meta.env.DEV`、`type X = {...}`、`querySelector<HTMLElement>()`、`x!.y` 非空断言）**原样进了浏览器** → 解析时抛 SyntaxError → **整块脚本作废**。

> 之前只修过 `as unknown as` 一种写法，其余 TS 语法仍在，所以故障一直存在。**dev 下 Vite 会转译，只有构建产物才炸** —— 这是最坑的地方。

**修复**（3 个文件）：
- `SearchPalette.astro`：删两个 `type` 声明块；7 处 `querySelector<T>` / 3 处 `querySelectorAll<T>` / 1 处 `new Map<K,V>` 去泛型；27 处 `x!.y` 去非空断言；5 处变量类型注解与函数签名去类型；`import.meta.env.DEV` → **运行时 `location.hostname` 判断**（内联脚本不能用构建期常量）
- `Toc.astro`：去泛型 + 删类型谓词 `(entry): entry is {...}`
- `albums/[id].astro`：去泛型

**验证**：产物 `dist/index.html` 中 5 类 TS 语法**全部为 0**；运行时探针确认 `window.__searchKeydown` 存在、搜索面板可打开（`panelOpened=true`）、目录脚本执行（`toc=true`）、黑胶开关生效（`vinylPlaying=true`）。

**教训**：这个坑的排查**不能只查一种写法**。全站 14 处 `data-astro-rerun` 脚本都要按「泛型 / 非空断言 / 类型注解 / as 断言 / type 声明 / import.meta」六类扫一遍。
